# Tallywise 产品界面原型

直接用浏览器打开 `index.html` 即可。样式、图标和交互均包含在单个 HTML 中，无需安装依赖或联网。

本次设计仅检查 `backend/` 中的路由、数据模型、请求结构和业务逻辑，没有读取现有前端代码。

## 已实现的原型交互

- 账本概览：切换月份、收入/支出趋势、月度汇总和分类占比。
- 收支明细：本地搜索、类型/账户筛选、分页，以及新增、编辑、删除记录。
- 我的账户：新增、更名、删除未被流水使用的账户；按所选月份展示收支。
- 收支分类：新增、更名、删除；保留后端的分类名称唯一、已使用分类不能删除或切换类型规则。
- 登录/注册：表单视觉与校验预览，不创建用户，不发送或存储密码。
- 演示记录保存在当前浏览器的 localStorage，清理浏览器数据或点击“重置演示”会清除修改。存储不可用时页面会提示。

## 与后端的对应关系

| 界面 | 当前后端接口 |
| --- | --- |
| 月度汇总 | `GET /api/summary?year=…&month=…` |
| 本月收支、趋势及分类占比 | `GET /api/transactions/{year}/{month}`，图表可基于完整月度数据计算 |
| 收支分页 | `GET /api/transactions/page?year=…&month=…&limit=…&cursor=…` |
| 新增、修改、删除收支 | `POST /api/transactions`、`PUT /api/transactions/{id}`、`DELETE /api/transactions/{id}` |
| 账户 | `GET/POST /api/accounts`、`PUT/DELETE /api/accounts/{id}` |
| 分类 | `GET /api/categories?money_type=收入或支出`、`POST /api/categories`、`PUT/DELETE /api/categories/{id}` |
| 用户 | `POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me` |

## 对接边界

这是交互设计原型，未连接后端或真实数据库。示例金额和记录不是用户的真实财务数据。

后续接入需注意：

- 新增流水必须发送 `Idempotency-Key`；同一次请求重试复用同一个键，不同请求使用新键。
- 登录使用 HttpOnly Cookie；部署时需要正确处理同源、Cookie 和凭据设置。
- 现有分页是游标分页，不能直接按任意页号跳转。原型的前后页操作需要维护游标历史。
- 搜索、类型/账户筛选与图表在原型中基于完整本地数据。后端目前没有这些搜索参数；对接时应获取完整月度数据后筛选，或另行扩展后端，不能只在已加载的一页数据上计算整月统计。
- “本月结余”是收入减支出，不等于账户真实余额。后端没有初始余额、转账、预算或多币种字段，界面未加入这些能力。
- 页面使用人民币符号作为当前设计展示约定；后端金额模型本身没有币种字段。
- 日均支出采用完整自然月天数作为分母；所有月度金额和笔数都由记录计算。
- 金额在原型计算中转换为整数分，提交数据形式保留两位小数的字符串。

文件独立于现有前端，可作为重新实现界面的设计参考。
